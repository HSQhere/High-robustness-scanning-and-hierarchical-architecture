# 04 实验：数据、指标、矩阵与复现规范

> 目标：让任何队员拿到同一份数据、同一份配置、同一个 commit，就能复现同一张表。
> 当前实验只覆盖**步骤 4（光照均衡 + 二值化）**；其余阶段只有接口，没有可报告的数据。

## 1. 数据集

### 1.1 数据来源

| 数据集 | 位置 | 内容 | 用途 | 是否入库 |
|---|---|---|---|---|
| `qr_samples` | `layers/04_binarize/data/input/qr_samples/` | 53 张唯一图：40 光照 + 11 基础条件 + 2 透视条件 | 步骤 4 主实验 | **是** |

### 1.2 划分规则

- **调参集 / 冻结验收集物理隔离**，同一帧及其裁切、增强派生图不得跨集。
- 当前只有合成集，**没有正式验收集**；所有结果只能称“实验”，不能称“验收通过”。
- 40 张光照样本与 11 个基础条件用于调参/行为检查；2 个透视条件只做行为检查；正式冻结集待现场采集后建立。
- 任何新增样本必须登记：来源、采集参数、真值、许可、是否可入库。

### 1.3 真值与命名

- 文件名含义：`<条件>_<参数>_<序号>.png`，例如 `far_120_00.png`、`illum_glare_hard_a090_00.png`。
- 模块真值来自生成器（旧 `tools/qr_eval`）：
  - `clean_320=12.8 px`、`clean_200=8.0`、`far_120=4.8`、`far_80=3.2`、`dim/blur=9.6`；
  - `illum_*=8.0`；
  - 旋转图按扫描线投影 `9.6 / cos(θ)` 计（仅对扫描线有意义）。
- 透视条件没有精确单模块真值，只统计解码与失败模式。
- `manifest.csv` 记录期望文本（当前统一 `156+123+516+231`）与真值。

## 2. 指标

### 2.1 模块尺度估计

| 指标 | 定义 | 说明 |
|---|---|---|
| `fail` | 没有返回有效 `module_px` | 不能把 0 当有效值 |
| `ambiguous` | 最高分箱支持度 < 2 | 有值但不可信 |
| `error_mean/max` | `|estimate - gt|` 的均值/最大值（px） | 只在有真值的图上统计 |
| `le_0_5` / `le_1` | 误差 ≤0.5 / ≤1.0 px 的图数 | 便于看分布 |
| `latency_p50/p95` | 估计器自身耗时 | 不含下游解码 |

### 2.2 解码

必须分别报告：

- `original`：原图直接解码。
- `equalized`：光照均衡图解码。
- `binary`：自适应二值图解码。
- `union`：三路任一成功。
- 按后端分：`cv2.QRCodeDetector`、`WeChatQRCode`、`ZXing`、`Quirc`。
- 任务码合法率：文本非空 **且** `ParseTaskCode` 通过。

> 只报 `union` 会掩盖单路退化；只报单路会低估实际链路。两个都要报。

### 2.3 质量与代价

| 指标 | 定义 | 用途 |
|---|---|---|
| `saturation_ratio` | 灰度 ≥250 的像素比例 | 判断信息是否不可逆丢失 |
| `dark_ratio` | 灰度 ≤5 的像素比例 | 判断欠曝/阴影死区 |
| `missing_area_ratio` | 不可读模块面积 / 码面积 | 触发修补/重拍 |
| `psnr/ssim` | 与 clean 参考图比较 | 合成集增强质量 |
| `cnn_latency_ms` | 修补/超分模型耗时 | 代价函数 |
| `cnn_uncertainty` | 重建残差/不确定性 | 生成结果可信度 |

### 2.4 延迟

- 报告 p50/p95/p99，不用平均值代替尾延迟。
- 必须注明：机器、CPU/GPU、OpenCV/后端版本、图像尺寸、是否含模型加载。
- 旧实验的 Python 耗时**不能**直接当作 C++/Jetson 指标。

## 3. 步骤 4 实验矩阵

### E4.1 估计器对照（核心）

| 变体 | 说明 |
|---|---|
| `scanline` | 多阈值 + 1:1:3:1:1 游程，0.5 px 分箱，支持度/拟合误差打分 |
| `canny_strict` | 字面相邻比例 `9/11, 11/27, 27/11, 11/9`，T=0.2 |
| `canny_norm` | 归一化比例向量 `[9,11,27,11,9]/67`，尺度无关 |
| `canny_norm_round` | `canny_norm` + 模块四舍五入到整数像素 |
| `canny_relaxed` | 放宽比例/拟合容差 |
| `hybrid` | 同时运行 `canny_norm` 与 `scanline`；相对差 ≤20% 时优先 Canny，分歧大时以 scanline 为准 |

数据：40 张 `illum_*`、11 个基础条件、2 个透视条件（各取一张唯一图，共 53 张）。
输出：模块误差、失败/歧义、三路解码、union、p50 耗时。
C++ 实测（OpenCV 4.14）：`hybrid` 0 失败、模块误差 mean 0.06 / max 0.19 px、三路 union 52/53；`blur_1` 与 `rot_45` 正确回退扫描线。

### E4.2 预处理消融

| 因子 | 水平 | 观察指标 |
|---|---|---|
| 去噪 | none / median3 / bilateral / gaussian | 模块误差、三路解码、耗时 |
| 均值窗 | 1× / 3× module | 二值解码、PSNR/SSIM |
| 闭运算核 | 2× / 3× / 4× module | 光照图平坦度、解码 |
| 缩放常数 | 180 / 200 / 220 | 过曝/欠曝比例、解码 |
| 自适应 C | 0 / 3 / 5 | 二值图黑/白比例、解码 |
| 阈值方式 | mean / gaussian | 解码、耗时 |

每个因子只变一个，其余固定；报告主效应，不做未经验证的多因子调参。

### E4.3 三路输出必要性

- 分别统计 original / equalized / binary 的失败集合，验证“失败集合不重叠”。
- 必须给出 union 与单路差值；若某路长期无贡献，才能讨论裁剪。

### E4.4 真实 ROI 抽查

- 从后续现场采集的 ROI 帧（多角度/遮挡/镜面光/色温/缩放）抽帧后跑步骤 4。
- 重点记录：局部镜面高光、半透明遮罩、实体遮挡、色温差异、缩放。
- 观察：`saturation_ratio` 与 `missing_area_ratio` 是否能区分“可救”和“不可救”。

### E4.5 C++ 与 Python 黄金对照

- 用同一批图、同一组参数，Python 参考实现与 C++ 实现逐像素比较。
- 模块尺度：整数/半像素量化差异必须为 0；浮点估计容差 `≤1e-3 px`。
- 二值图：不一致像素比例 `≤0.1%`，且差异必须能由 OpenCV 版本/边界处理解释。
- 中间图（illumination/equalized）：PSNR `≥50 dB` 或逐像素容差 `≤1`。
- 不通过则不得把 C++ 结果接入流水线。

### E4.6 与解码的联合实验

- 固定解码器（WeChat/ZXing），比较“只用原图”“原图+均衡+二值”“加三帧”的端到端成功率。
- 记录每增加一路/一帧的耗时增量，验证是否值得。
- 任务码合法率单独统计，不能只看“解出文本”。

## 4. 旧实验基线（可复现，供重构对照）

> 来源：旧 `perception` 工程，Python + OpenCV 4.10，合成集；**不是 C++/Jetson 数据**。
> 详细数据见旧仓库 `tests/qrv2/qr_dynamic_illumination_demo/experiments/README.md`。

### 4.1 估计器对照（40 张光照 + 11 基础 + 2 透视）

| 数据集 | 变体 | 失败 | 模块误差 mean/max (px) | 三路解码 orig/eq/bin/union | p50 |
|---|---|---:|---|---|---:|
| 40 光照 | scanline | 0 | 0 / 0 | 37 / 39 / 39 / **40** | 105–116 ms |
| 40 光照 | canny_norm | 0 | 0.06 / 0.143 | 37 / 39 / 39 / **40** | 23–25 ms |
| 40 光照 | canny_norm_round | 0 | 0 / 0 | 37 / 39 / 39 / **40** | 23–25 ms |
| 11 基础 | scanline | 0 | 0.078 / 0.215 | 11 / 11 / 10 / **11** | 137–153 ms |
| 11 基础 | canny_strict | **2** | 0.83 / 6.457 | 9 / 9 / 8 / 9 | 19–22 ms |
| 11 基础 | canny_norm | 0 | 0.931 / 6.171 | 11 / 11 / 10 / **11** | 32–33 ms |
| 2 透视 | scanline | 0 | — | 1 / 1 / 1 / 1 | 98–109 ms |
| 2 透视 | canny_norm | 0 | — | 1 / 1 / 1 / 1 | 19 ms |

> 表中 `orig/eq/bin/union` 是成功张数；2 个透视条件里只有 `persp_15` 可解，`persp_30` 三路都失败。

关键结论：

1. 正常 8 px 模块上，Canny 与扫描线解码等价；Canny 在 Python 下快 4.5–7 倍。
2. `canny_strict` 是尺度相关的，小模块/大角度会直接失败；`canny_norm` 更接近论文“比例向量”的原意。
3. `blur_1` 上所有 Canny 变体都估成 3.0–3.4 px（真值 9.6），扫描线正确；必须加置信度门控 + 回退。
4. 透视下两者都不可靠；透视问题应由 ROI/几何解决，不是尺度估计器。
5. 二值图单路最高 39/40，三路并集 40/40；**不能只保留二值图**。

### 4.2 边界

- 旧实验是 280×280 合成图和少量 1280×800 实拍帧，不是 8MP ROI。
- 光照集部分样本原图即可解码，提升主要集中在 `glare_hard`；不能夸大成“通用提升”。
- 论文参数（Canny 阈值、Close1 核、比例容差）未公开，当前是工程复现，不是官方实现。

### 4.3 C++ 实测（2026-11-23，OpenCV 4.14）

环境：MSYS2 GCC 16.2、OpenCV 4.14、`denoise=none`、53 张唯一图。
完整结果：[`step4_baseline/report.md`](../layers/04_binarize/experiments/results/step4_baseline/report.md)。

| 数据集 | 变体 | 失败 | 歧义 | 模块误差 mean/max (px) | 三路解码 orig/eq/bin/union | p50/p95 (ms) |
|---|---|---:|---:|---|---:|---:|
| 40 光照 | scanline | 0 | 0 | 0.00 / 0.00 | 37/38/39/**40** | 1.46 / 1.75 |
| 40 光照 | canny_norm | 0 | 0 | 0.06 / 0.14 | 37/38/39/**40** | 1.16 / 1.38 |
| 40 光照 | hybrid | 0 | 0 | 0.06 / 0.14 | 37/38/39/**40** | 2.32 / 2.88 |
| 11 基础 | scanline | 0 | 0 | 0.08 / 0.21 | 11/11/10/**11** | 2.34 / 4.17 |
| 11 基础 | canny_strict | 2 | 3 | 0.83 / 6.46 | 11/9/8/**11** | 1.50 / 3.93 |
| 11 基础 | canny_norm | 0 | 0 | 0.93 / 6.17 | 11/11/10/**11** | 1.41 / 3.64 |
| 11 基础 | hybrid | 0 | 0 | **0.04 / 0.19** | 11/11/10/**11** | 3.42 / 5.57 |
| 2 透视 | scanline / canny_norm / hybrid | 0 | 0 | — | 1/1/1/**1** | 1.2–2.8 |
| 全部 53 | scanline | 0 | 0 | 0.02 / 0.21 | 49/50/50/**52** | 1.51 / 2.58 |
| 全部 53 | canny_norm | 0 | 0 | 0.25 / 6.17 | 49/50/50/**52** | 1.17 / 1.78 |
| 全部 53 | hybrid | 0 | 0 | **0.06 / 0.19** | 49/50/50/**52** | 2.39 / 3.70 |

C++ 结论：

1. `hybrid` 在 53 张上 0 失败，模块误差 max 0.19 px；`blur_1` 与 `rot_45` 都正确回退到扫描线。
2. `canny_strict` 仍有 2 张失败、5 张歧义；`canny_norm` 无失败，但 `blur_1` 误差 6.17 px（“自信地错”）。
3. `hybrid` 的 p50 约 2.4 ms，代价是同时跑两路；相比 Python 的 100+ ms 已不是瓶颈。
4. 解码仍用 `cv2.QRCodeDetector` 的非空文本计数，任务码合法性尚未接入。
5. 与旧 Python 基线相比，Equalized 单路从 39/40 变为 38/40，属于 OpenCV 版本/解码器差异；union 仍为 40/40。

## 5. 复现规范

### 5.1 目录

```text
layers/<阶段>/experiments/
├── configs/                 # 本实验的 JSON 配置
├── results/
│   └── <run_id>/
│       ├── run_meta.json    # commit / 版本 / 配置哈希 / 数据哈希 / 机器
│       ├── metrics.json     # 聚合指标
│       ├── per_image.csv    # 逐图结果
│       └── report.md        # 人读报告
└── README.md                # 如何运行
```

`data/output/` 只放可视化中间图（默认不入 Git）；`experiments/results/` 放可提交的小结果文件。

## 7. 数据许可与大文件

- 外部数据集（Szentandrási、Dubská 等）必须保留 LICENSE 与 PROVENANCE；不得把未授权数据提交到仓库。
